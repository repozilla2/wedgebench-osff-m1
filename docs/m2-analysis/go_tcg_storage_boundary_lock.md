## 2. Parser Boundary

**Function:** `plainCom.Receive(ses *Session) ([]byte, error)`
**File:** `pkg/core/communication.go` in `go-tcg-storage`
**Constructor:** `core.NewPlainCommunication(d drive.DriveIntf, hp HostProperties, tp TPerProperties) *plainCom`

This is the correct boundary because it:

- Takes a raw byte buffer (read via `d.IFRecv`) and returns a structured payload or error
- Implements the full ComPacket → Packet → SubPacket framing chain in BigEndian binary
- Is below session/workflow logic (`NewControlSession`, `MethodCall`)
- Is above raw transport — `DriveIntf.IFRecv` is the hardware call, which is replaced by a fake
- Is deterministic: same buffer in → same result out, no hidden state

**Boundary call sequence at probe time:**

```
fakeDrive.IFRecv  ← injects corpus bytes into the buffer
core.NewPlainCommunication(fakeDrive, InitialHostProperties, InitialTPerProperties)
  .Receive(&core.Session{ComID: core.ComID(input.ComID)})
```

**Session construction:** only `ComID` is set. `TSN`, `HSN`, and sequence fields are zero-value, consistent with `InitialTPerProperties.SequenceNumbers = false`.

## 5. Non-Goals

The following are explicitly out of scope for this integration:

- **No hardware.** The probe never opens a physical device. `DriveIntf.IFRecv` is satisfied by `fakeDrive`, which copies the test buffer. No NVMe, SCSI, or ATA device is required.
- **No upstream merge dependency.** The integration does not require any patch, fork, or pending PR in the `open-source-firmware/go-tcg-storage` repository. The local `replace` directive in `go.mod` is sufficient.
- **No physical timing claims.** `latency_us` in probe output and evidence artifacts is host adapter wall-clock time. It is not a claim about real TPer response latency, hardware throughput, or firmware timing behavior. It varies between runs and is explicitly excluded from deterministic evidence claims (see `latency_note` in the artifact schema).
- **No exploit discovery.** WedgeBench observes whether the parser accepts, rejects, or wedges on corpus inputs. It does not identify security vulnerabilities, demonstrate exploitation paths, or make claims about firmware safety properties.
- **No formal verification.** Evidence artifacts record behavioral outcomes. They are not proofs of correctness, formal specifications, or certification artifacts.
